# Pooled metrics — confusion matrix + AUC-ROC for every model

Generated by `scripts/pool_metrics.py` from the prediction dumps in `results/preds_yolo/`
and `results/preds_deim/`. 18 models: 10 YOLO26 cells at 640 px and 8 DEIMv2 variants.

## How each number was produced

Each model has three fold checkpoints. Each is run on **the fold it was held out from**, and
the three are pooled — so every matrix below covers **all 90 annotations**, each predicted by
a model that never trained on it. **The 30-annotation test set is not touched.**

Matching is greedy by descending confidence at IoU ≥ 0.50. IoU for oriented boxes is exact
polygon intersection (`cv2.intersectConvexConvex`), never ultralytics' ProbIoU surrogate,
so the OBB, HBB and DETR rows are on one scale.

### The operating threshold is per-model, and it has to be

A confusion matrix needs an operating point. 0.25 is the ultralytics convention, but YOLO26
applies NMS and **DEIMv2 does not** — it emits 300 unsuppressed queries per image, so at 0.25
several survive on the same hand and every one after the first is counted as a false alarm.
The effect is not small: at 0.25, DEIMv2 records 44–150 false alarms against YOLO26's 10–25,
and `deimv2/m` scores macro-F1 **0.46** despite an AP50-95 of 0.829.

Each model is therefore reported at its own macro-F1-optimal threshold (swept 0.05–0.95), with
the fixed-0.25 columns kept for reference. **Caveat:** that threshold is chosen on the same
predictions it scores, so P/R/F1 are an upper bound. AUC is threshold-free and immune to this,
which is why it is the metric to lead with when comparing architectures.

## The finding: one hard pair, and it is the anatomically adjacent one

Summed 4×4 over the 35 working models (macro AUC ≥ 0.9):

| ground truth ↓ / predicted → | thumbout | openhand | closedhand | background |
|---|---|---|---|---|
| **thumbout** | **784** | 2 | 87 | 177 |
| **openhand** | 0 | **988** | 0 | 62 |
| **closedhand** | 89 | 1 | **784** | 176 |
| **background** | 124 | 114 | 82 | — |

Per-class AUC across those 35 models:

| class | mean AUC | worst model |
|---|---|---|
| openhand | 0.9979 | 0.9650 |
| thumbout | 0.9497 | 0.8533 |
| closedhand | 0.9550 | 0.8906 |

**176 of the 179 class confusions (98.3%) are thumbout ↔ closedhand. Only 3 ever
involve openhand.** openhand is essentially perfectly separable (mean AUC 0.9985,
worst 0.9922); thumbout and closedhand sit at ~0.95 because they are
confused with each other and almost nothing else.

That is the expected physical result: thumbout is a closed fist with the thumb extended, so it
differs from closedhand by one digit, while openhand differs from both in global hand shape.
The same pair caused the annotation errors found during dataset construction, where four fists
were labelled thumbout and had to be detected by their negative `thumb_straight` values.

**Consequences for the instrument.** The gesture vocabulary is not uniformly hard — it is easy
except for one pair. If reliability matters more than the current vocabulary, the cheapest fix
is redesigning `thumbout` to differ from `closedhand` by more than a thumb. If the vocabulary
is fixed, the errors are predictable and can be handled at the MIDI-mapping layer rather than
demanding a better model.

## The other finding: AP and AUC rank the two architectures differently

DEIMv2 wins on AP50-95 (l = 0.843 ± 0.024 vs YOLO26's best 0.815 ± 0.037) and **finds more
hands** — `deimv2/l` misses 2 of 90 where YOLO26 misses 6–19. But YOLO26 takes the top four
AUC slots. The two metrics measure different things and the gap is real: DEIMv2 localises
better, YOLO26 classifies better once it has localised.

For a gesture instrument, a miss and a misclassification are not equally bad — a missed hand
is a dropped note, a misclassification is a wrong note. Which architecture to prefer follows
from that, not from either metric alone.
